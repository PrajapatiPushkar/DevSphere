# ADR 0035: Resume PDF Rendering & Export Foundation

## Status
Accepted

## Date
2026-08-28

## Context
Following Lesson 35's introduction of the HTML rendering foundation, developers require a production-grade PDF export endpoint (`GET /api/v1/resumes/{resumeId}/render/pdf`) to download clean, printable resume files. The PDF export architecture must maintain visual consistency with HTML preview without duplicating layout logic or bypassing compilation and security protections.

## Decision
We introduce PDF export using the existing deterministic HTML rendering pipeline via `OpenHTMLtoPDF` (`com.openhtmltopdf:openhtmltopdf-pdfbox:1.0.10`).

### Architecture Pipeline
```
Career Data
    ↓
Resume Profile
    ↓
Resume Compilation Engine (ResumeCompilationService)
    ↓
CompiledResume (CompiledResumeResponse)
    ↓
HTML Renderer (HtmlResumeRenderer)
    ↓
HTML Document
    ↓
PDF Renderer (OpenHtmlToPdfResumeRenderer)
    ↓
PDF Bytes
```

### Key Architectural Decisions
1. **Single Visual Source of Truth**: PDF export converts HTML generated by `HtmlResumeRenderer` into PDF bytes via `PdfResumeRenderer` abstraction (`OpenHtmlToPdfResumeRenderer`). Layout code is not duplicated.
2. **In-Process Java Library Choice**: `OpenHTMLtoPDF` is used for in-process HTML5/CSS2.1+ page rendering without external headless browsers (Playwright/Chromium).
3. **Decoupled Architecture**: The PDF renderer performs **zero database, JPA, Redis, Kafka, or network calls**.
4. **Security & Resource Isolation**:
   - `PdfRendererBuilder` operates with null baseUri to prevent resolving arbitrary HTTP/HTTPS endpoints or local files.
   - HTML pre-escaping and URL sanitization established in Lesson 35 are preserved.
   - Headers use sanitized filenames via `ResumeFilenameSanitizer` to prevent HTTP response header injection and path traversal (`..`, `/`, `\`, control chars).
5. **Download Behavior**: Endpoint returns `200 OK`, `Content-Type: application/pdf`, and `Content-Disposition: attachment; filename="<sanitized_filename>.pdf"`.
6. **Observability**: Metrics tracked via Micrometer counter `devsphere_resume_pdf_export_total` (tags: `status=success|failure`, `format=pdf`, `template=<template>`) and timer `devsphere_resume_pdf_export_duration`.

## What is Intentionally NOT Implemented
- DOCX generation.
- AI/LLM resume tailoring or ATS scoring.
- Job matching or external job platform integration.
- Asynchronous PDF generation, Kafka events (`ResumePdfGeneratedEvent`), or outbox changes.
- Persistent file storage (`resume_files` table, S3, or local disk persistence).
- Redis PDF caching.

## Consequences
### Positive
- Strict visual consistency between HTML preview and PDF export.
- Zero external process dependencies (no headless browser memory overhead).
- Bulletproof security isolation against XSS, header injection, and SSRF.
- Clean separation of concerns allowing future renderers (e.g., DOCX) to reuse compiled models.

### Tradeoffs
- OpenHTMLtoPDF requires XHTML-well-formed HTML input (self-closing meta tags).
- Memory allocation for temporary PDF byte array generation.
