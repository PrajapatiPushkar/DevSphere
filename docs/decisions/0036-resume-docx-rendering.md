# 36. Resume DOCX Rendering & Export Foundation

Date: 2026-08-28

## Status

Accepted

## Context

Lesson 35 introduced HTML preview rendering for resumes, and Lesson 36 introduced PDF document rendering. Developers need the ability to export their compiled resumes into editable Microsoft Word (`.docx`) documents for manual customization or submission to job portals that require Word format.

The DOCX rendering engine must consume the existing deterministic `CompiledResumeResponse` generated by `ResumeCompilationService` without relying on HTML-to-DOCX conversion or PDF-to-DOCX conversion.

## Decision

Introduce editable DOCX resume export directly from `CompiledResumeResponse` using Apache POI (`org.apache.poi:poi-ooxml`).

### Architecture

```
CompiledResumeResponse
          ↓
  DocxResumeRenderer (ApachePoiDocxResumeRenderer)
          ↓
    Editable DOCX
          ↓
  HTTP Download (200 OK)
```

### Key Technical Choices:
1. **Direct Compilation Consumption**: The DOCX renderer takes `CompiledResumeResponse` directly, ensuring exact content consistency with HTML and PDF renderers.
2. **Library**: Apache POI `poi-ooxml:5.2.5` for native OOXML document generation.
3. **Renderer Boundary**: Keep Apache POI implementation details (`XWPFDocument`, `XWPFParagraph`, `XWPFRun`) encapsulated strictly inside the `com.devsphere.user.renderer` package.
4. **Template Support**: Implement centralized styling (`DocxTemplateStyle`) for `PROFESSIONAL`, `MODERN`, and `MINIMAL` templates.
5. **A4 Page Layout**: Configure page dimensions (A4 portrait) and margins directly on document section properties.
6. **Security & Hyperlinks**: Treat all content as plain text (XSS safe) and validate URLs to allow only `http://` / `https://` clickable hyperlinks.
7. **Observability**: Log operational execution safely without PII or binary bytes, and record Micrometer metrics (`devsphere_resume_docx_export_total`, `devsphere_resume_docx_export_duration`).

### Explicitly Excluded Features (Lesson 37 Boundaries):
- AI / LLM integration
- ATS scoring
- Job matching & external job platform integration
- Resume tailoring
- Asynchronous document generation
- Kafka events for DOCX generation
- Persistent document storage (S3 / database)
- Redis caching for generated documents
- User-uploaded DOCX templates or rich Word template editor

## Consequences

### Positive
- Users receive fully editable Microsoft Word documents matching their chosen template.
- HTML, PDF, and DOCX renderers remain completely independent.
- High content consistency across all rendering formats.
- Safe plain-text rendering prevents XSS vulnerabilities.
- Zero database or schema migrations required.

### Negative / Tradeoffs
- DOCX flow layout is dependent on the viewer application (Word, Google Docs, LibreOffice) and client system fonts.
- Complex CSS layout rules cannot be directly translated into POI document structures.
- Apache POI dependency adds library weight to `user-service`.
