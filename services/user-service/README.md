# DevSphere User Service

## Overview

The **User Service** is the core application domain microservice responsible for managing authenticated user profile information in DevSphere. It operates on port `8082` and maintains strict database ownership over `devsphere_user`.

```
Client ──► API Gateway (:8080) ──[JWT Validation]──► User Service (:8082) ──► MySQL (devsphere_user)
```

---

## Domain Responsibilities

- **User Profile Management**: `first_name`, `last_name`, `display_name`, `bio`, `phone_number`, `created_at`, `updated_at`.
- **Identity Alignment**: Uses canonical `userId` generated by `Auth Service` as profile identity key.
- **Asynchronous Event Consumption**: Listens to Apache Kafka topic `devsphere.user.v1` (Consumer Group: `devsphere-user-service`) and initializes user profiles idempotently upon consuming `UserRegisteredEvent`.
- **Lazy Profile Fallback**: Fallback profile initialization on `GET /api/v1/users/me` if an authenticated request arrives before Kafka event consumption completes.
- **Zero Authentication Logic**: Does not handle user registration, logins, password verification, or JWT generation/parsing.

---

## Database Ownership & Boundaries

- **Database Name**: `devsphere_user`
- **Table**: `user_profiles`
- **Constraints**: `user_id` MUST be unique (`UNIQUE KEY`).
- **Isolation Principle**: Does not share database tables or foreign keys with `devsphere_auth`. Cross-database direct queries are strictly forbidden.

## Configuration & Environment Variables

| Variable | Description | Default Value |
|---|---|---|
| `SERVER_PORT` | HTTP Server Port | `8082` |
| `DB_HOST` | MySQL Hostname | `localhost` |
| `DB_PORT` | MySQL Port | `3306` |
| `DB_NAME` | User Database Name | `devsphere_user` |
| `DB_USERNAME` | Database Username | `root` |
| `DB_PASSWORD` | Database Password | *(empty)* |

## API Endpoints

| Method | Endpoint | Protection | Description |
|---|---|---|---|
| `GET` | `/api/v1/users/me` | Protected (Gateway JWT) | Retrieves or lazily initializes current user's profile |
| `PUT` | `/api/v1/users/me` | Protected (Gateway JWT) | Updates current user's profile details |
| `GET` | `/actuator/health` | Public | Actuator health status check |

---

## Security Model & Header Propagation

User Service relies on trusted authentication context propagated by the **API Gateway**:
1. The API Gateway validates the client's Bearer JWT.
2. The Gateway strips any client-supplied `X-Authenticated-User-Id` header.
3. The Gateway injects `X-Authenticated-User-Id: <userId>` into downstream requests.
4. User Service reads `X-Authenticated-User-Id` to identify the user. Requests missing this header return `401 Unauthorized`.

Direct public access to port `8082` in production is disabled. All external requests must pass through API Gateway.
